# Bugfix Requirements Document

## Introduction

Подписка на уведомления (`notify = 1`) сбрасывается в `0` при повторном сохранении номера телефона. Это происходит потому, что `savePhone` использует `INSERT OR REPLACE`, который удаляет существующую строку целиком и вставляет новую с дефолтными значениями. В результате пользователи, подписавшиеся на уведомления, перестают их получать после повторного шаринга номера телефона.

## Bug Analysis

### Current Behavior (Defect)

1.1 WHEN пользователь вызывает `savePhone` с уже существующим `user_id` (повторный шаринг номера) THEN система удаляет старую строку пользователя и вставляет новую строку с `notify = 0`, сбрасывая флаг подписки

1.2 WHEN пользователь с `notify = 1` повторно делится номером телефона через команду `/start` или нажатием кнопки THEN система сохраняет новый номер, но при этом `notify` становится `0` и пользователь перестаёт получать уведомления

### Expected Behavior (Correct)

2.1 WHEN пользователь вызывает `savePhone` с уже существующим `user_id` THEN система SHALL обновить только `phone_number` для этого пользователя, сохранив текущее значение `notify` без изменений

2.2 WHEN пользователь с `notify = 1` повторно делится номером телефона THEN система SHALL сохранить новый номер и сохранить `notify = 1`, чтобы пользователь продолжал получать уведомления

### Unchanged Behavior (Regression Prevention)

3.1 WHEN пользователь впервые делится номером телефона (новый `user_id`) THEN система SHALL CONTINUE TO создавать новую запись с `notify = 0` по умолчанию

3.2 WHEN пользователь вызывает `/notify` THEN система SHALL CONTINUE TO устанавливать `notify = 1` через `setNotify`

3.3 WHEN пользователь вызывает `/unsubscribe` THEN система SHALL CONTINUE TO устанавливать `notify = 0` через `setNotify`

3.4 WHEN `checkAndSendNotifications` запрашивает подписчиков THEN система SHALL CONTINUE TO возвращать только пользователей с `notify = 1`
